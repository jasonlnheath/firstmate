Outcome

Hibernate works again. The captain's end state is live: clean hibernate entry and resume, 5% critical battery = Hibernate (AC+DC), lid-close = sleep then auto-hibernate after 120 s (this Boot Camp firmware exposes no LIDACTION ACPI device, so HIBERNATEIDLE is the working mechanism). One residual defect (backlight dark at S4 resume) is masked by a self-healing step in the on-box recovery task.

Root cause and fix (A1)

The chronic 0xC0000225 resume failures were downstream: every hibernate ENTRY died dirty (Kernel-Power 41, BugcheckCode 0), leaving an aborted hiberfile the boot manager rejected at the next boot. BCD was diagnosed sound (single coherent resume object, correct filedevice/filepath); the failing stage was the entry transition. The running hypervisor was the veto: powercfg /a itself named it ("The hypervisor does not support this standby state"). With bcdedit /set hypervisorlaunchtype off (reboot), hibernate re-enabled full-type, and one real shutdown /h cycle: clean entry (no 6008/41/id16), clean resume (boot type 0x2, no 0x0 fallback, same OS session), Apple T1 stack healthy after. The hypervisor stays off - nothing on the box used WSL/VMs/HVCI. Revert: bcdedit /set hypervisorlaunchtype auto.

Power config changes (all with reverts in the on-box log): powercfg /h /type full (6.4 GB hiberfile); BATACTIONCRIT = 2 (Hibernate) AC+DC; HIBERNATEIDLE = 120 s AC+DC (revert: AC 0 / DC 1500). LIDACTION was attempted and confirmed inert on this firmware.

Attempted and closed (A2b, A2a)

A2b - reinstall of the Boot Camp-era AMD display driver (u0390451, 31.0.12027.9001) from the pre-onset driver snapshot: stages but cannot bind on build 26200, proven three independent ways (rank refusal, forced-install API ERROR_NO_MORE_ITEMS, rescan falling to Microsoft Basic Display Adapter); rolled back immediately to the 2025 driver (30.0.13045.22003) from a pre-made rollback copy; no hibernate cycle spent. A2a - Aug-24 update uninstall: deliberately held (firstmate word), since the entry crash it targeted is cured by A1. Hard caps respected: one hibernate test cycle used of three allowed.

Residual defect: backlight dark at S4 resume (self-healed)

Captain-confirmed: the panel is dark after wake; lid close/open revives it (hardware fine; the 2025 AMD driver's resume path skips the panel re-enable). No display-class events are logged at the failure - it is silent. Mitigation deployed: the on-box RecoverAppleSpiStack scheduled task (fires on resume and boot, 45 s delay) now ends each run with a gentle backlight kick - re-apply the current brightness via WmiSetBrightness (the brightness-key pathway), falling back to a runtime-resolved monitor-devnode restart; non-fatal by contract, before/after levels logged; kick mechanics proven live on-box. Root-cause levers left for a future captain decision: newer Adrenalin, release-channel OS move, or Driver Verifier (unapproved).

Touch Bar protections standing

The landed fix remains: RecoverAppleSpiStack task Ready with three triggers (system start + Kernel-Power 107 + Kernel-Boot 27, 45 s delay, battery-safe), runtime device resolution (no pinned instance IDs), rc 3010/50 treated as success-with-reboot-pending. Its trigger set was extended during this campaign after the dirty-boot path was shown to miss the event-only triggers.
